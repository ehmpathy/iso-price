## hazards

### 🔴 H1 — config: `"private": true` added to package.json  → **real, fixed**

- what: upgrade added `"private": true` (HEAD had no `private` key)
- why it breaks:
  - `npm publish` refuses a private package → `.publish-npm.yml` fails on next release tag
  - `provision/github.repo/resources.ts` now maps `visibility: pkg.private === false ? 'public' : 'private'` (fail closed). with `true`, the `provision` workflow plan would flip the public repo `ehmpathy/iso-price` to private on apply from main
- proof: `gh api repos/ehmpathy/iso-price` → `{"private":false,"visibility":"public"}`; this package publishes to npm
- fix: set `"private": false` (explicit, as the fail-closed provision logic requires)
- verify: `node -p "require('./package.json').private"` → `false`; provision plan on pr shows no visibility diff

- proof: build ran; `grepsafe --pattern '@src' --path dist` → 0 matches; `dist/contract/index.js` requires `../domain.objects/*`. ~~hazard~~
